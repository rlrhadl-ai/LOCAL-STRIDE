# 코스 안전 신고 기능

## 이용 흐름

1. 코스 상세 또는 실제 러닝 화면 → **코스 안전 제보 → 사진으로 신고**.
2. 이메일 계정 로그인 → 사진 촬영 또는 사진 선택 → GPS 현재 위치 확인 또는 지도에서 지점 선택.
3. 문제 유형·위험 정도·5~500자 설명 입력 → 위치·사진 공개에 동의 → 접수.
4. 신고 위치는 해당 코스 지도에 노란색 **확인 전** 지점으로 표시된다. 신고 사진·설명은 운영자 확인 전 공개되지 않는다.
5. `/admin` → **코스 안전 신고**에서 사진·좌표를 확인하고 처리 상태, 공개 안내, 내부 메모를 저장한다.
6. 확인 완료/처리 중은 빨간 지점으로 표시된다. 해결 완료/비공개는 공개 목록과 지도에서 제외된다. 열려 있는 화면은 60초마다 또는 창에 다시 포커스할 때 갱신하며 수동 새로고침도 제공한다.

러닝 중 신고창을 열면 진행 중인 러닝을 일시정지한다. 신고 후에는 러너가 직접 재개한다. 해당 코스의 신고를 조회하는 기능이며, 모든 코스의 신고를 한 번에 보여주는 도시 전체 지도는 이번 범위에 포함하지 않는다. 신고는 LOCAL STRIDE 운영팀에 전달되며, 지자체 민원을 자동으로 접수하지 않는다.

## 관리 항목

- 유형: 노면 파손 / 시설물 파손 / 통행 방해 / 조명 불량 / 기타 불편
- 위험 정도: 불편 / 주의 / 위험 (신고자 선택, 객관적인 안전 인증이 아님)
- 상태: 확인 전 / 확인 완료 / 처리 중 / 해결 완료 / 비공개
- 신고 사진, 코스·지역, 위도·경도, GPS/지도 선택 구분, GPS 정확도, 접수·변경 시각
- 상태·유형·코스 필터, 페이지당 25건, 전체 상태별 통계
- 처리 상태·담당 관리자·내부 메모 이력, 공개 처리 안내
- 현재 필터 결과 CSV 최대 10,000건 (UTC 시각, 수식 실행 방지, UTF-8 BOM)

## 권한과 저장 정책

- 신고 등록: 이메일 계정 로그인 필요. 익명 기기 ID만으로 등록 불가.
- 공개 목록: 로그인 없이 공개 코스의 미해결 신고만 제공. 신고자 ID·이메일·내부 메모·사진 바이너리 제외.
- 사진: 접수/비공개는 신고자 또는 관리자만 열 수 있다. 확인 완료/처리 중/해결 완료는 연결 코스가 공개 상태인 경우 사진 직접 조회도 허용한다. 해결 사진까지 접근을 차단하려면 상태를 비공개로 변경한다.
- 사진 권한 확인과 바이트 조회를 한 번의 DB 쿼리로 수행한다. 사진을 정적 공개 uploads 경로에 저장하지 않으며 응답은 `no-store`이다.
- 업로드는 1장, 최대 5MB, JPEG/PNG/WebP, 최대 2,500만 화소. 확장자 대신 서버에서 실제 파일을 디코딩한다. GIF/SVG/다중 페이지 이미지 등은 거부한다.
- 저장본은 회전 보정 후 최대 1200px JPEG로 변환하고 EXIF·ICC 등 원본 메타데이터를 제거한다. 최대 1MB의 변환본만 PostgreSQL BYTEA에 저장하며 원본 파일은 보관하지 않는다. 자동 얼굴/번호판 모자이크는 포함하지 않으므로 관리자가 공개 전에 확인한다.
- GPS 오차 100m 이하, 코스 선분으로부터 500m 이내, 한국 좌표 범위를 검증한다. GPS 값은 클라이언트 입력이므로 현장 방문을 보증하는 인증은 아니다.
- 클라이언트 UUID와 DB 고유 제약으로 실패 후 재시도·동시 전송의 중복 저장을 방지한다.
- 프로세스별 계정당 10분간 10회 업로드 시도 제한. 여러 API 인스턴스로 확장할 때는 공유 저장소 기반 제한으로 변경해야 한다.
- 관리자 수정은 version 조건과 트랜잭션으로 동시 수정 덮어쓰기를 막고 이력을 함께 기록한다.
- 신고가 있는 코스는 삭제 대신 비공개로 전환한다. DB 외래키도 신고자/코스 삭제를 제한하므로 향후 계정 삭제 기능에는 신고 익명화·정리 정책을 연결해야 한다.

## 운영 반영 순서

이 문서는 배포 절차를 기록하며, 운영 DB 마이그레이션과 운영 배포는 아직 실행하지 않았다. 2026-09-16 배포 준비 시 GitHub 원격 연결은 확인했으나, 현재 작업 환경에는 EC2 접속용 SSH 키·AWS CLI 인증 설정이 없고 브라우저 제어 연결도 실패했다. 프론트만 먼저 공개하지 않도록 변경 사항은 `codex/course-hazard-reports` 준비 브랜치로 분리하며, API·DB 반영 확인 후에만 main에 통합한다.

1. DB 백업과 운영 환경 변수, Node 지원 버전, API 서버 디스크/DB 용량을 확인한다.
2. API 서버의 새 코드에서 아래 명령을 실행한다. 운영 DB에 `migrate reset`, `db push`, 개발 시드를 실행하지 않는다.

```sh
cd api
npm ci
npx prisma generate
npm run build
npx prisma migrate deploy
```

3. API 프로세스를 재시작한다. 신규 테이블 `HazardReport`, `HazardReportHistory`와 enum 3개를 추가하는 마이그레이션이며 기존 데이터의 삭제·재설정은 없다.
4. API가 정상 동작한 뒤 웹을 빌드·배포한다. 기존 `NEXT_PUBLIC_API_URL` 및 API 프록시 설정을 유지한다. HTTPS에서 위치 권한을 실제 기기로 확인한다.
5. 프록시/CDN의 요청 본문 제한이 5MB 파일과 multipart 오버헤드를 허용하는지 확인한다. Nginx 사용 시 해당 location에 `client_max_body_size 8m;` 등의 충분한 한도가 필요하다. 앞단 호스팅 제한이 더 작으면 앱 업로드 한도도 함께 낮춘다.
6. 테스트 계정으로 소형·대형 사진, GPS 허용/거부, 관리자 확인/해결/비공개, 새로고침, CSV를 확인한다. 카메라 입력은 OS의 파일 선택기 기반이며 실제 iOS/Android 카메라·사진 형식 호환성은 현장 확인이 필요하다. HEIC 직접 업로드는 지원하지 않는다.

신고량 증가 시 DB BYTEA를 비공개 객체 스토리지로 옮기되, 지금의 접근 권한 정책은 유지해야 한다. 정식 운영 전에 사진·좌표 보관 기간, 삭제 요청 창구, 운영자 확인 주기와 긴급 위험 대응 절차를 확정한다.

### 지도 배경

화면 검증에서 기존 CARTO 배경에 API 키 요구 워터마크가 발견되어, 신고 위치 지도와 코스/러닝 지도는 공통 `web/lib/map-tiles.ts` 설정을 사용하도록 변경했다. 기본값은 OSM 표준 타일이며, `NEXT_PUBLIC_MAP_TILE_URL`과 `NEXT_PUBLIC_MAP_TILE_ATTRIBUTION`으로 계약한 지도 제공자를 설정할 수 있다. 두 환경 변수는 공개 클라이언트 번들에 들어가므로 비밀 키를 넣지 않는다. 브라우저 기본 캐시와 Referer를 유지하고 저작권을 표시한다. 대량 다운로드·오프라인 저장은 구현하지 않았다. 자동 브라우저 테스트에서는 타일 요청도 합성 데이터로 대체한다. 운영 트래픽 증가 시 [OSM 타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/)의 용량 제한과 가용성 보장 부재를 고려해 계약형 서비스를 사용한다.

## 검증

```sh
cd api
npx prisma generate
npm run test:hazards
cd ../web
npm run build
```

- `api/tests/hazards.test.cjs`: 메모리 Prisma 대역을 사용한 HTTP 계약·권한·파일 처리 테스트 14개. 실제 DB 접속 없음.
- `api/tests/hazards.migration.cjs`: PGlite를 별도 설치 후 `PGLITE_MODULE`에 모듈 경로를 지정해 실행. 격리된 PostgreSQL/WASM에서 모든 SQL 마이그레이션, 바이너리 사진 저장, 기본값·고유키·좌표·외래키 제약 확인. 운영 PostgreSQL/Prisma 연결을 대체하는 종단간 테스트는 아님.
- `web/tests/hazards.browser.cjs`: 로컬 빌드를 포트 4317에서 실행한 뒤 Playwright로 검증. `PLAYWRIGHT_MODULE`, 필요 시 `CHROME_PATH` 지정. 모든 API는 합성 테스트 데이터로 가로채며 운영 사이트에 쓰지 않음. GPS·직접 위치 선택, 사진·설명, 오류 유지·재시도, 익명 로그인 안내, 러닝 화면, 관리자 처리 이력·필터·CSV를 검증.
- 실제 운영 DB 연결, 실제 기기 카메라와 현장 GPS, 프록시 업로드 한도는 배포 후 별도 확인 대상이다.
